# Bugaoshan Changelog

按目标版本和提交范围整理最终生效的变化。提交、diff 是取证材料，不逐条转抄。

## 输入

- 目标版本、目标 revision、比较基准、现有 `CHANGELOG.md`。版本来自用户指定、Release PR 或可信发布上下文，不从 tag 或 `pubspec.yaml` 猜测。
- 缺版本时先梳理变更再补问；发布日期以用户指定为准，未定则省略日期。
- 默认只输出 Markdown；要求改文件时只改对应版本，不改版本号、元数据，不提交、不发布。历史定位见 [history-and-release.md](references/history-and-release.md)。

## 流程

1. **定范围**：记录基准与终点 SHA，确认是完整版本、同版本增量还是预览晋升。增量以已有文案实际覆盖的提交为界；无法确认的部分标为待核对。
2. **验效果**：读 diff、调用点、测试，确认入口、平台、系统、学生类型、认证与网络条件。界面名称以 `lib/l10n/app_zh.arb` 为准。核对到的条件只用于判断条目是否成立，不全部写进正文。
3. **合并净变更**：同一功能的新增、修复、调整合并为一条；完全撤销的不收；多平台一致则合并，仅生效条件不同时用一句注明。
4. **筛选分类**：只收用户可感知的功能、体验变化和缺陷修复，不含内部重构、测试、工具链、CI/文档、版本号与元数据提交。分类仅 `Added` / `Changed` / `Fixed` / `Removed`，按此顺序。
5. **写文案**：中文，`-` 列表，按重要性排序。每条一句话、一行（约 30 字），只写“哪里、变成了什么”。不写实现、原因、旧行为对比、操作步骤、括号举例和“提示：”；条件只在决定能否使用时保留一个短语（如“仅 iOS 16.1+”）。写不下就删细节或拆条。

   反例：
   > 新增「通知与提醒」：可在软件设置中开启课前提醒，自定义提前量（5 / 10 / 15 / 30 / 60 分钟，可多选）、免打扰时段，并随时查看当前已排期的提醒。……提示：Android 14 及以上系统默认不授予「精确闹钟」权限，未授权时提醒会降级为非精确唤醒，锁屏状态下可能有 9~15 分钟延迟

   应为：
   > 新增「通知与提醒」：可设置课前提醒、提前量与免打扰时段；Android 14 起需授予精确闹钟权限，否则提醒可能延迟

   已确认的 issue/PR 用 `(#编号)`；作者按现有风格，必要时查 author 与 `Co-authored-by`。

## 版本章节

```markdown
## [X.Y.Z] - YYYY-MM-DD

### Added
- 新增功能，一句话说完。

### Fixed
- 修复具体问题（#123）。
```

预览只维护 `## [Unreleased]`，不新建 preview/RC 章节；正式版写 `## [X.Y.Z]`，日期未定则省略。`[Unreleased]` 与更高版本章节不能同时有内容。合并同名章节，新版本放顶部，不改历史版本。

交付前检查：范围对应、撤销与重复已处理、平台与分发限制准确、条目均为单句且无残留解释；改文件后跑 `git diff --check`。纯文案只输出最终 Markdown；改文件后简短说明改动范围与待核对项。
