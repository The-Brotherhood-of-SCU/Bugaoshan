## 页面行为

| 能力 | 代码实现 | 真机操作范围（用户已反馈通过） |
| --- | --- | --- |
| 外链 | 项目仓库、官网、团队、手册及 EULA 链接显式使用 `externalApplication`，捕获拒绝或打开失败并提示 | 系统浏览器/目标应用是否正确打开 |
| 选图 | 报修、办事大厅、课表背景共用 OH 副本中的图库选择接口；取消不改表单，错误提示并写入 AppLog，页面关闭后不更新 UI | 取消、选中图片、重复点击、选图后返回和上传 |
| 背景图 | 新文件复制成功后才更新设置并清理旧文件；使用独立文件名，复制失败保留旧背景；继续使用上游裁剪和主题提取逻辑 | 原图、裁剪、重启恢复，以及失败时旧背景可用 |
| 文件保存 | 沿用第二阶段 `file_picker_ohos` 与保存 bytes 补丁，取消与失败独立处理 | ICS 文件内容、保存位置及取消 |
| 相册保存 | 沿用第二阶段系统保存弹窗和原图字节处理 | 取消、保存结果和图片格式 |
| 文件打开 | 附件弹窗和下载管理通过 `openLocalFile` 检查插件返回值，失败有页面提示 | 有/无接收应用、文件已被删除、重复点击 |
| 分享 | 单文件和多文件统一检查路径并处理错误；日志导出不在分享失败后继续显示成功提示 | 日志、单附件、同名多附件及再次分享 |
| 日历 | 课表、考表、校历统一启用 OH 入口，把生成的 ICS 路径传给 `bugaoshan/update.importIcsToCalendar` | 日历应用接收文件并由用户确认导入 |

日历返回 `opened` 仅代表系统接受了打开请求，Dart 不显示“已导入到日历”。
没有接收端、URI 转换失败或系统拒绝时，原生返回错误，由现有页面显示导入失败。
分享补丁只确认系统面板调用，不跟踪接收应用后续处理，返回 `unavailable` 表示没有最终选择结果；
不会将关闭分享面板记作已完成分享或确定的取消。面板使用单目标选择模式，
多文件仍作为同一批内容传给目标应用，同时兼容文本/URI 记录。

## 插件源码问题与补丁

以下依据为 OH 锁中固定提交的源码阅读，缓存源码未直接编辑。

- `open_filex 4.7.0`：原实现未等待 `startAbility` 的 Promise，还把错误码比较写成了赋值。
  补丁等待系统结果、正确比较错误码，使用 `fileUri.getUriFromPath` 生成应用文件 URI，
  授予读取权限，并阻止在结果未返回时覆盖上一调用的回调。
- `share_plus 12.0.1`：原实现使用异步 `forEach` 复制文件，在复制完成前返回 URI 列表，
  handler 还会提前回复成功；若干错误分支只写日志。补丁先完整准备文件，再等待分享面板调用，
  把准备/打开失败传回 Flutter，保证单次回复。每次使用独立缓存，文件句柄在 finally 中关闭，
  同名附件分目录存放；不在下一次分享开始时删除接收端可能仍在读取的文件。
- `image_picker_ohos 0.8.13+7`：原实现把系统错误和读取失败当作取消，复制出错时还会重复关闭文件句柄。
  补丁以空选择表示取消，以 FlutterError 表示错误，清理 pending 状态，并捕获单图读取/处理异常。

分享产生的文件位于应用缓存目录，保留给接收端读取，由系统缓存回收管理；没有加入主动清理策略。
系统分享调用已纳入用户此次平台流程验收；接收应用后续处理结果仍遵循上述返回语义。

## 权限与数据边界

当前三个选图入口都使用 `PhotoViewPicker` 的图库选择，不调用相机。所选图片由插件复制到
应用缓存后提供给 Dart。文件保存使用系统选择器，相册保存通过系统确认弹窗。
附件和日历通过 Want 传递文件 URI 并授予临时读取权限。按这些调用方式，宿主沿用
`ohos.permission.INTERNET`，不新增相册全量读取、相机或日历直接写入权限。

后续代码审查保留 SCU token/账号凭据的原有键，增加退出恢复标记和会话并发保护；报修 token
采用包含账号归属的独立安全存储记录，旧无归属 token 不自动复用，按需重新 SSO。
安全存储插件保持原 Preferences 名称、前缀和已有加密算法，读写失败不重置全部数据。
数据库路径和 schema 不变。
当前上游已有 SQLite `1 → 2` 的 campus 字段迁移；旧 OH 安装对应源码仍不完整，不能据此
宣称旧用户迁移已通过。账户切换、登录续期已获用户真机确认；旧安装数据及覆盖升级继续单独验证，未加入清空数据逻辑。

余额趋势、课程查询和培养方案继续使用当前上游业务代码；办事大厅、报修、Passpoint 的
错误处理与认证边界通过上述补丁修复。上述四项功能以用户真机反馈记为通过；未记录代理执行的编译或测试结果。
签名仍安排在最后阶段，双 SDK 校验仍在阶段六。
