# ADR-0011：课表日期为全局数字格式，顶栏完整、表头只取月日

- 状态：已接受并实施
- 决策日期：2026-10-26

## 背景

课表顶栏与网格表头的日期此前走两条互不相干的路径：顶栏按语言拼出
`2026/10/18`（窄屏省年份，仅英文资源里带 `MM/DD` 文案），表头则用
`dateMonthDayCompact` 输出 `10/19`，而中文的 `dateMonthDay` 仍是「10月19日」。
结果是同一屏里出现两种顺序、两种分隔符，且中文长日期在窄列里被
`FittedBox` 压缩到难以辨认——低分辨率屏上 5~7 列平摊后每列只有 60px 上下。

## 决策

新增全局偏好 `DateDisplayFormat`（`lib/models/date_display_format.dart`），
持久化在 `AppConfigProvider.dateDisplayFormat`（SharedPreferences key
`dateDisplayFormat`，存 enum index，默认 `monthDayYearSlash`）。
入口为「软件设置 → 课程表样式」页显示设置区内的下拉框，九种完整日期写法，
即时生效。不单设独立页面：该页已有课表实时预览，改完立刻能看到顶栏与表头的
实际效果，多开一页只会让用户在两处之间来回跳。

同一个格式有两种消费方式，共用排列与分隔符：

1. `formatFull`：课表左上角顶栏，输出完整日期（含年份）。
2. `formatMonthDay`：网格表头每一列，丢掉年份只留月与日。

即选择 `19.08.2026` 时，顶栏是 `19.08.2026`、表头是 `19.08`；
选择 `2026-08-19` 时，表头是 `08-19`。日期与节假日弹窗（`special_day_sheet`）
同样使用 `formatMonthDay`，与点开的表头列保持一致。

落地范围限定在课表域：顶栏、表头、特殊日弹窗、课表导出图片。其余页面
（考试安排、提醒设置、校历等）的日期文案不在本次范围内，仍按各自现状输出。

历法语义不变：日期仍由 `ScheduleConfig.dateForCourseDay` 计算，本偏好只决定
渲染文本，不参与任何周次或日期计算。

## 后果

正面影响：

- 同一屏内顺序、分隔符统一，且不再随界面语言变化。
- 表头宽度与语言无关，低分辨率屏与中文界面不再被长日期挤压。
- 新增格式只需在枚举里加一项并同步单测；调用方无需改动。

代价与约束：

- 中文用户不再看到「10月19日」这类母语写法；这是为窄列可读性做的取舍。
- 该偏好只覆盖课表；若后续要求全 App 统一，需要逐个替换写死 `yyyy-MM-dd`
  的页面，并重新评估哪些页面属于「窄空间」。
- 自定义格式（任意排列组合）未开放，避免无法穷举的下拉项与溢出回归面。
