# ADR-0011：课表日期为四种数字格式，默认跟随系统语言

- 状态：已接受并实施
- 决策日期：2026-10-26（2026-10-31 按评审意见收敛为四种格式）

## 背景

课表顶栏与网格表头的日期此前走两条互不相干的路径：顶栏按语言拼出
`2026/10/18`（窄屏省年份，仅英文资源里带 `MM/DD` 文案），表头则用
`dateMonthDayCompact` 输出 `10/19`，而中文的 `dateMonthDay` 仍是「10月19日」。
结果是同一屏里出现两种顺序、两种分隔符，且中文长日期在窄列里被
`FittedBox` 压缩到难以辨认——低分辨率屏上 5~7 列平摊后每列只有 60px 上下。

初版曾提供九种完整日期写法（顺序 × 分隔符 × 年份位数）。评审指出两点：
选项太多，且「日月反转」的写法在没有年份锚点时容易误读。于是先收敛为
「顺序跟语言、分隔符二选一」，进一步实测发现 CLDR 连分隔符也一并给出，
最终收敛为零设置项。

## 决策

日期格式只保留四种常见写法，统一用 `/` 分隔、年份四位、月日补零：

| 格式 | 顶栏 | 表头 |
|---|---|---|
| `MM/DD/YYYY` | 10/26/2026 | 10/26 |
| `DD/MM/YYYY` | 26/10/2026 | 26/10 |
| `YYYY/MM/DD` | 2026/10/26 | 10/26 |
| `YYYY/DD/MM` | 2026/26/10 | 26/10 |

`DateDisplayFormat`（`lib/models/date_display_format.dart`）是这个四值枚举，
持久化在 `AppConfigProvider.dateDisplayFormat`（key `dateDisplayFormat`，
存 enum index）。**null 表示跟随系统**，这是默认状态。

默认值由系统语言映射：`fromLocale(locale)` 读 `intl` 的
`DateFormat.yMd(locale).pattern`，按 `y`、`M`、`d` 的先后判定排列。
CLDR 里 zh 是 `y/M/d` → `YYYY/MM/DD`，en 是 `M/d/y` → `MM/DD/YYYY`。
用户不需要先改一次设置才能得到符合习惯的写法。

入口为「软件设置 → 课程表样式」页显示设置区内的下拉框，即时生效。

两种消费方式：

1. `formatFull`：课表左上角顶栏，带年份。
2. `formatMonthDay`：网格表头每一列，只留月与日。

日期与节假日弹窗（`special_day_sheet`）与课表导出图片同样使用
`formatMonthDay`，与点开的表头列保持一致。

选项为什么从九个收敛到四个：初版按「顺序 × 分隔符 × 年份位数」穷举出九种，
评审指出两位年份（`26/10/26`）与点号、横线写法在小屏上没有收益，反而让
「日月反转」在没有年份锚点时容易误读。年份本身保留：顶栏是完整日期展示，
表头跟随顶栏的月日顺序，年前年后可切。

落地范围限定在课表域：顶栏、表头、特殊日弹窗、课表导出图片。其余页面
（考试安排、提醒设置、校历等）的日期文案不在本次范围内，仍按各自现状输出。

历法语义不变：日期仍由 `ScheduleConfig.dateForCourseDay` 计算，本格式只决定
渲染文本，不参与任何周次或日期计算。

## 后果

正面影响：

- 同一屏内顺序、分隔符统一，且不再随界面语言的文案长度变化。
- 表头宽度恒定，低分辨率屏与中文界面不再被长日期挤压。
- 默认值自动匹配系统语言，用户不需要先改设置。
- 只有四个选项，没有两位年份与点号/横线等易混写法。

代价与约束：

- 分隔符固定为 `/`，不接受点号或横线。
- 默认映射依赖 `intl` 的 locale 数据（由 `flutter_localizations` 在 app 内
  初始化）；纯 Dart 单测里需先 pump 带 delegate 的 MaterialApp，否则回落
  `MM/DD/YYYY`。
- 中文用户不再看到「10月19日」这类母语写法，为窄列可读性做的取舍。
- 该偏好只覆盖课表；若后续要求全 App 统一，需要逐个替换写死 `yyyy-MM-dd`
  的页面，并重新评估哪些页面属于「窄空间」。
- 自定义格式（任意排列组合）不开放，避免无法穷举的下拉项与溢出回归面。
